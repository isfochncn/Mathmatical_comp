日期：2026-09-11。依据为《题意解析与建模衔接备忘录》及四问数学建模规范。本记录说明代码修订及实际验证结果；既有 `out/` 旧结果不能作为本次修订后的数值结论。

## 已付费弃电与储能优先（当前生效规则）

依据用户本轮要求，问题二、三、4-2、4-3允许弃置实在无法消纳的已付费普通购电。新增假设、完整约束和优先级见《题意解析与建模衔接备忘录》第4.0节。问题一仍采用原来的确定性自然日模型。

- 规划仅允许冻结承诺段弃电，新计划、合法调整量和次日前瞻不得主动安排弃电。先最少弃电，再最低预测电费，最后在前两者保持最优的容差内优先减少较早时段的普通与紧急购电，利用已有储能腾出空间。
- 实际反馈先尽量充电吸收过购，不能吸收的部分记录为弃购电；缺电时优先用电池，再紧急补购。禁止额外放电制造损耗来美化弃电量，但保留用于负荷的同时充放电。
- 弃电与弃光分别核算；全部普通购电仍按原O/A标签付费，弃电不退款、不撤销承诺，也不扣除账单购电量。满电和充电功率受限均可造成弃电，事件表分别记录。
- 母线平衡与消纳上界均纳入弃电变量，独立验证器逐段核对最少必要弃电量、设备约束和费用。首次执行仍为1月1日00:10，SOC仍为6000 kWh，表格的时间对应不变。

新产物版本为`main-model-v4-paid-spill`。`spill_events.csv`记录弃电时刻、数量、已付费购电量、负荷、段首末SOC和容量/功率触限标志；`summary.json`新增有效利用购电量和弃电事件统计。模板中的购电量及费用仍按完整付费口径导出。

当前验证：**79项自动化测试通过**（73.63秒），编译与差异检查通过；真实附件四个滚动分支均完成两天连续执行和Excel导出。执行窗口为2025年1月1日00:10至1月3日00:10，各288段，均从6000 kWh开始，中途不重置。独立脚本再次核对了时间映射、母线/SOC、逐段最低必要弃电量和能量总账，CSV弃电合计与summary一致。

## 年初00:10起算修订（继续有效）

问题二、三、4-2、4-3从2025年1月1日00:10起算，初始SOC=6000 kWh。此前00:00—00:10保持缺失，不填补、不优化、不执行、不计费，也不加入预测历史。问题一使用已给定的典型日，仍保留原有自然日循环约束。

| 对象 | 最新对应关系 |
|---|---|
| 绝对时间坐标 | 保持以1月1日00:00为坐标零点；第一条执行记录的绝对分钟为10，数组下标为0 |
| 首日初始化 | `E_{1,1}=B_{1,0}=6000`，不生成`E_{1,0}`的已执行状态 |
| 首日计划 | 00:10制定，只提交当天余下143段；首轮规划287段，终点1月3日00:00 |
| 后续计划 | 仍在每天00:00制定，6/12/18点调整权限按自然时钟执行 |
| result首格 | 1月1日00:10—00:20，读取附件第一天第一项 |

截至本次显式约束修订，全量73项测试通过，包括首日143段计划、首行144格、原始数据首项映射、跨午夜计划和SOC衔接、首日部分账单与Excel标签回读。真实附件短程复测仍发现过购不可行：问题二在1月1日22:10反馈无解，问题三及问题四两分支在00:20滚动窗口无解，冲突数值与下方记录相同。因此跳过年初缺失段并未消除这项既有模型可行性问题。

## 购电余量可消纳约束显式化（前轮记录）

按用户最新要求，规划层新增具名约束 `purchase_absorption_power` 和 `purchase_absorption_capacity`：外网购电、紧急购电、可用光伏和电池放电满足负荷后，剩余供电必须同时满足单段充电输入上限和电池剩余容量。实际反馈LP与独立验证器加入同样的两项检查。它们由已有物理等式和边界隐含成立，显式列出便于审查与诊断；不限制外网绕过电池直接供电，不把预测替换成未来实测，也不取消已冻结承诺。

新增回归算例覆盖：2000 kWh外网直接供电且电池不动作、充电功率不足、满电时容量不足，以及低价购电储能后在高价段放电减少费用。本轮73项测试通过，编译及差异检查通过。真实附件1月1日复测仍在问题二22:10、问题三及问题四两分支00:20出现与上文相同的不可行；这些显式约束不改变原有可行域，也未消除冻结承诺与后续预测或实测之间的冲突。

## 已修订的实现

| 范围 | 当前行为 | 主要文件 |
|---|---|---|
| 物理定义 | 充电变量为实际存入量，放电变量为实际送达量；两者每段上限均为 750 kWh，效率分别计入母线与 SOC；允许同时充放电 | `src/microgrid/physics.py`、`simulation.py`、`planning.py` |
| 问题一 | 自然日 144 段确定性 LP，首末 SOC 均为 6000，紧急购电固定为零；结果行通过典型日循环映射 | `absolute_run.py` |
| 滚动窗口 | 主模型每十分钟重算 `[a,b+1440)`；今天余段与完整次日联合优化；报告截止日期不截断规划窗口 | `simulation.py`、`planning.py` |
| 信息权限 | 问题二不用附件三；问题三、4-2、4-3仅使用当前已发布且覆盖目标时段的光伏预报；其余由成熟历史补齐 | `forecast.py` |
| 预测与单位 | 同钟点历史、最近24小时回退均只用已完成观测；午夜不漏掉上一日；历史光伏 kW 只除以6一次；首次无历史用注明来源的附件一典型日先验 | `forecast.py` |
| 价格 | 问题二、三按附件一价格重复；问题四不把上段实测当当前报价，也不读取当前段事后均价做当前决策；执行后用该段实际价结算 | `forecast.py`、`simulation.py` |
| 交易权限 | 首日00:10、后续零点只提交当天计划；问题二及4-2冻结普通购电；问题三及4-3仅在6、12、18点修改当天未执行部分；次日前瞻不提前承诺 | `simulation.py` |
| 调整费用 | 可调段目标为 `p*y + 0.5*p*max(y-O,0) + 0.5*p_now*max(O+A-y,0)`；次日前瞻仍用普通费率；执行 O/A 精确递推，罚金累计且以发生时的实际价结算 | `planning.py`、`settlement.py` |
| 执行反馈 | 依次最少弃购电、最少紧急购电、最小目标偏差、最小吞吐；过购先储存，负荷缺口优先用储能；弃光单独记录 | `simulation.py` |
| 不可行处理 | 冻结承诺不能释放、失败区间不能跳过；允许不可避免的已付费弃电。新增合法动作后仍无解或校验失败才停止合格导出 | `solver.py`、`planning.py`、`simulation.py` |
| 初始化与跨日 | 始终从1月1日00:10连续执行，后续不重置 SOC；`run_from` 只改变报告起点；保留附件最后一列提供的次年首段真实值；更远未知实测为缺失值，不伪造年度延伸 | `timeline.py`、`absolute_run.py` |
| 原计划与导出 | 单独归档零点原计划，避免用调整后的 O 替代；自然日与 result 行分别计费；后续日期六个四小时块使用当天自身午夜段，首日首块从00:10起；缺段、缺边界、缺标签或账单不符拒绝导出 | `absolute_run.py`、`export.py`、`cli.py` |
| 校验与实验 | 逐段母线、SOC、弃光和设备边界独立校验；账单按事件复算并核对权限；导出再次检查保存的账本；额外购电边界和不同重算频率只能进入显式命名的独立实验 | `validation.py`、`settlement.py`、`cli.py` |

保存结果新增 `forecast_audit.json`（各轮信息截止时刻、窗口及来源摘要）、`initial_plans.json`（首日00:10及后续零点原计划）和 `settlement_events.json`（执行标签与调减事件）。`trajectory.npz` 保留绝对时间顺序的物理数组，另以 `result_*` 字段表达问题一模板顺序。校验版本为 `main-model-v4-paid-spill`，旧版本产物必须重算。

辅助复核脚本也已更正：不再把母线失衡解释为预测误差，不再要求弃光与富余重复记账，不再用执行 O 代替零点计划；模板哈希复核只比较既有基准，不在验证过程中重写基准。
