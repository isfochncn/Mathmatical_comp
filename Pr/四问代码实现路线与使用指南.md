# 运行与严格格式导出指南

当前模型适用范围、已验证参数和待修项目以[模型优化定稿与验证档案](模型优化定稿与验证档案.md)为准。本文件替代原先“尚未实现”的设计指南，原文已进入清理前源码快照。

## 1. 入口与环境

从项目根目录运行，使用现有 `.venv/Scripts/python.exe`。主实现只有 `src/microgrid/`；独立实验位于 `tools/experiments/`，不作默认生产入口。

| 入口 | 作用 |
|---|---|
| `tools/run_selected_period.py` | 问题2/3/4通用连续运行、版本预检、轨迹与账本保存 |
| `tools/prepare_strict_result.py` | 从实际轨迹与账本复算模板数据，生成result_payload.json |
| `tools/build_strict_result.mjs` | 从原模板副本生成严格格式xlsx，生成预览 |
| `tools/verify_strict_result.py` | 独立回读xlsx，复核时间、逐格值、自然日SOC、账单和原始哈希 |
| `microgrid.cli audit` | 数据与求解器只读审计 |
| `microgrid.cli run/export` | 问题一及历史兼容接口；滚动分支正式交付使用上述严格格式流程 |

Node使用Codex提供的运行环境；导出器默认从Node可执行文件相邻的 `../node_modules` 查找artifact-tool。其他环境可显式设置 `ARTIFACT_TOOL_NODE_MODULES`。不再将依赖复制或链接到任何结果目录。

## 2. 先核实版本，再运行

```powershell
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem3 --describe
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem4-3 --pv-method pooled --describe
```

`--describe`不求解、不创建输出。问题三应显示ReportAwareForecaster、report_blend、repeated价格；问题四auto/report_blend应显示CumulativeReportForecaster和historical价格。显式pooled为已知有缺陷的历史复现。此前清理阶段的auto拒绝已被本轮三个修正后的新入口替代。

当前问题四版本为report-economic-reserve-v5，describe还应显示3%冷启动预留、阶段匹配误差和80/20成本权衡（4-2首周50/50）。此前v3/v4使用同名预测器但参数及目标不同，复现须使用其留存源码包，不能只凭类名判断版本。

问题三全年：

```powershell
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem3 --pv-method report_blend --run-from 2025-02-01 --run-to 2025-12-31 --out outputs/问题三_新全年运行
```

问题三两月：将run-to改为2025-02-28。问题二使用同一入口，problem改为problem2。

问题四旧版两月复现：

```powershell
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem4-2 --pv-method pooled --run-to 2025-02-28 --out outputs/问题四_旧版新复现_4-2
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem4-3 --pv-method pooled --run-to 2025-02-28 --out outputs/问题四_旧版新复现_4-3
```

这些命令复现有已知缺陷的历史策略，不表示已修复问题四。所有滚动运行均从1月1日00:10、6000 kWh连续执行；run-from只控制报告起点。每次使用新目录，已有status.json时拒绝覆盖。长计算前保存 `run_contract.json`，并在日志记录进度。

问题四修正后的两周检验（前一周前置，后一周报告）：

```powershell

.venv/Scripts/python.exe tools/run_selected_period.py --problem problem4-3 --pv-method report_blend --run-from 2025-01-08 --run-to 2025-01-14 --out outputs/问题四_新两周检验/4-3
```

最终v5全年：将run-from设为2025-02-01、run-to设为2025-12-31，仍从年初连续执行。当前全年归档和冻结策略见[问题四v5全年计算档案](问题四v5全年计算档案.md)。复用既有107项测试时须先确认运行源码与最终v5两周档案的哈希一致。

## 3. 严格模板输出

以下以新问题三全年目录为例；问题二、四同样适用。

```powershell
$runOutput = 'outputs/问题三_新全年运行'
.venv/Scripts/python.exe tools/prepare_strict_result.py --out $runOutput
$nodeExe = Join-Path $env:USERPROFILE '.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe'
& $nodeExe tools/build_strict_result.mjs $runOutput
.venv/Scripts/python.exe tools/verify_strict_result.py --out $runOutput
```

导出保留原模板表名、表头、日期排列、列宽及储电时刻位置。购电行00:10起，充放电和SOC按自然日，跨日末列按真实时间归属。只填计算过的报告日期，其他模板行留空。最后检查各工作表预览，保留 `saved_result_checks.json` 和视觉检查记录。

本流程不修改 `data/附件5/`。预测目标及风险惩罚不得计入真实费用。`source_and_template_hashes.json`是运行时版本约束，当前代码变更后不得篡改旧记录以跳过不匹配；历史版本需从对应源码快照在隔离位置恢复。

## 5. 留档与清理规则

- 原始附件、正式result、完整轨迹、账本、预测审计、关键核验JSON保留。
- 临时指针不作版本选择依据；实验输入使用显式目录。
- 重复月度运行/导出脚本已由通用入口替代；仍有独立用途的实验保留在experiments并注明范围。
- 清理前源代码、旧脚本及Pr文档压缩保存在 `outputs/源码留档/`，含提交号、逐文件哈希。
- 预览与依赖可再生，新的运行不得把node_modules带入结果目录或Git。物理清理若被环境限制，记录残留，不得把待删除项写成已删除。
