# 问题三光伏预报校正与一月至二月预测检验

> 当前适用范围见[模型优化定稿与验证档案](模型优化定稿与验证档案.md)。本文件的预测优化与连续调度证据属于问题三；问题四仅有旧版连续测试和局部诊断，不能套用本文件的改善结论。

第一阶段仅增加独立候选预测器 `ReportAwareForecaster`，检验预测本身，不求解储能或购电主模型。第二阶段按用户要求将选出的动态融合方法接入问题三，并连续运行一月至二月的购电调度。负荷沿用现有周周期与近期偏差模型，用来隔离光伏改进的影响。

## 信息与时间口径

输入为附件1冷启动先验、附件2历史实测、附件3在形成时刻已经发布的光伏预报。所有实测训练样本必须满足区间结束时间不晚于当前预测形成时间，不使用尚未发布的预报。发布节点为自然时钟00、06、12、18点；首日00:00—00:10跳过，从00:10起检验。

唯一时段表沿用result归属：一月为1月1日00:10至2月1日00:10，二月为2月1日00:10至3月1日00:10，均不含终点。分别为4464、4032个十分钟时段。自然日发布节点不随表格归属平移。

## 候选方法

1. 用最近7日同刻成熟实测形成十分钟历史曲线。每个报告小时的六段按历史曲线占比分配，六段之和严格保持该原始报告小时的电量。历史小时全部为零时采用均匀分配。
2. 对每个发布时间和目标小时分别估计乘法校正系数。最近28日对应预报与成熟实际小时均值配对，权重为 `2^(-滞后日数/7)`。通过原点加权最小二乘系数向1收缩，收缩项为 `2 × sum(w*原报平方)/sum(w)`；至少7个有效日才启用，系数限制在[0,2]。这些都是技术假设，不是题面参数。
3. 在历史预测与校正预报之间动态融合。用过去14日、按各自历史形成时间重建的预测做样本，权重半衰期7日。按目标小时估计最小平方误差的融合权重并限制在[0,1]。设每段两候选预测之差为delta，分母加入 `4 × sum(w*该小时各段delta平方和)/sum(w)`，向历史预测收缩；至少7个成熟日启用。预报没有增益时，允许权重为0。
4. 节点之间的滚动预测使用当前发布之后、最近1小时已完成区间的光伏预测残差中位数进行修正，按 `exp(-提前分钟/120)` 衰减。修正后截断为非负，不将白天正残差带入原预测为零的夜间。节点预测一旦发出，不用后来实测改写。

小时形状分配保持原始小时总量；统计校正和融合本身会改变该总量，不能声称最终优化预测仍等于原始预报总量。报告覆盖之外仍采用因果历史预测。

## 选择与测试

预先比较历史、仅小时形状修正、分小时校正、动态融合四种候选。只用1月15日00:10至2月1日00:10的节点预测MAE选择方法，选中动态融合。二月按已经选定的算法向前检验，仅允许使用当时已成熟的历史更新参数，没有根据二月得分重新挑选候选。

本次模型设计已经参考过二月的费用诊断。因此，尽管逐次预测保持因果，二月仍是开发回测，不能称为完全未参与设计的独立验证集。独立验证应另选月份。

除了逐时唯一时段，还检查各发布版本的0—6、6—12、12—24小时预测，以及相邻调整节点间累计净负荷低估峰值。发布版本表允许相同目标时间多次出现，其样本数不与唯一时段数相加。月度按目标时段的result归属划分。

## 二月结果

单位为每十分钟kWh的平均绝对误差（MAE）：

| 指标 | 旧方法 | 优化方法 |
|---|---:|---:|
| 发布节点后0—6小时光伏 | 40.069908 | 15.282902 |
| 十分钟滚动光伏 | 40.069908 | 11.021774 |
| 发布后6—12小时光伏 | 41.812789 | 17.661495 |
| 发布后12—24小时光伏 | 46.144487 | 18.615523 |
| 节点净负荷 | 51.164026 | 30.236017 |

仅使用历史的二月光伏MAE为19.428054，原始附件3报告为60.088294。优化后的节点预测不仅优于旧融合，也优于仅使用历史。负荷模型本次没有修改，其二月节点/滚动MAE分别为21.062215、20.269424。

不使用含大量夜间零值的MAPE。光伏正向误差表示高估发电；净负荷正向缺口表示实际净负荷超过预测。MAE下降不意味着所有偏差方向同时改善，也不直接等价于电费降低。尤其滚动预测更好不能赋予09:00等非调整节点普通增购权限。

## 复现与核验

预测测试入口为 `tools/experiments/evaluate_report_forecast.py --out <输出目录>`；代码不调用 `run_absolute`、`solve_window` 或其他调度求解入口。详细指标、逐时CSV、预测数组、候选选择记录和Excel保存在独立输出目录。

六项预测专用测试覆盖：原始小时能量保持、未来实测及未发布预报隔离、后续实测不改写已发布节点预测、禁止附件3时的权限隔离、冷启动及跨日窗口、夜间零发电保护。

## 接入问题三主模型

`RunConfig.pv_method` 有 `auto`、`pooled`、`report_blend` 三种取值。`auto` 在问题三且使用 adaptive 负荷模型时启用动态融合和滚动修正；问题二保留历史预测。2026-09-12后续修正已将问题四auto接入同一优化光伏及新累计压力路径，见[问题四三项修正与两周检验](问题四三项修正与两周检验.md)。本文件问题三历史指标不代表问题四表现。`pooled` 显式复现此前整体系数校准。

新策略标识为 `forecast_policy_version=report-hourly-blend-risk-v2`。历史联合误差路径由同一新预测器按过去各节点的信息截止重新形成，备用需求随新误差重新计算；风险分位仍为0.90，不能沿用旧预测器的误差缓存或把风险惩罚记入真实电费。

两月运行从2025年1月1日00:10、6000 kWh开始，每十分钟重新规划，一月至二月连续递推SOC。普通购电仍只能在题目规定节点调整。二月报告沿用00:10起的result行口径，一月作为前置运行保存。复现命令：

```
.venv/Scripts/python.exe tools/run_selected_period.py --problem problem3 --pv-method report_blend --run-to 2025-02-28 --out <新输出目录>
```

接入测试另核验问题分支路由和备用计算的信息隔离，共七项测试通过。调度费用结论必须依据此次主模型实际运行结果，不能由前述预测MAE直接推算。
