# 2026 实战检查清单

[返回导航](README.md)｜[上一章：代码实现](05-代码实现风格.md)｜[样本索引](07-样本索引与证据表.md)

本页把论文观察转化为比赛流程。`[官]` 项来自 2026-09-05 可见的官方规定；赛前仍需复核官网和所在赛区通知。

## 0. 开赛前准备

- [ ] 三人能共同完成“读题—建模—编程—写作—核验”，不把任何一环完全孤立。
- [ ] 备好透明基线、回归/时序、规划、仿真、敏感性等最小代码模板。
- [ ] 模板中没有学校、姓名、指导教师、往年队号等身份信息。
- [ ] 预演一次从空目录运行代码并重建论文表图。
- [ ] 阅读当年竞赛通知、论文格式、AI 使用和赛区补充规则。

## 1. 选题（建议 45—90 分钟内完成）

- [ ] 每题逐问标注任务类型、关键数据、核心约束和最终交付物。
- [ ] 至少提出一条可落地的基础路线，不以“模型听起来高级”为选择标准。
- [ ] 评估三项真实风险：数据质量、算法实现时间、验证难度。
- [ ] 判断后续问题是否依赖前问；避免选到只能完成第一问的题。
- [ ] 留一条替代路线，在主模型失败时仍能完成全文。

## 2. 读题与定义

- [ ] 把每问改写成输入—输出—约束—评价指标。
- [ ] 核对单位、时间/空间粒度、边界与附件字段。
- [ ] 明确“最优、合理、风险、有效”等词的可计算定义。
- [ ] 区分状态变量、参数、决策变量与随机变量。
- [ ] 画出各问依赖关系；记录题目中不能擅自改变的规则。

## 3. 数据处理

- [ ] 记录数据来源、下载/获取时间、许可与引用方式。
- [ ] 保留原始数据，只用脚本生成处理数据。
- [ ] 检查缺失、重复、异常、量纲、编码与组成数据约束。
- [ ] 防止未来信息、主体重复、全数据预处理造成泄漏。
- [ ] 可视化先服务于审计和假设，不以“图多”为目标。

## 4. 选模

- [ ] 每个模型对应一个明确困难；问题分析中写出选择理由。
- [ ] 先保留一个简单、透明的基线。
- [ ] 物理/几何规律能约束模型时先使用机理。
- [ ] 样本量、变量数量和模型复杂度相称。
- [ ] 多模型之间是串联、递进或校验关系，不是模型名陈列。
- [ ] 预测误差如何进入后续优化已经设计。

## 5. 求解

- [ ] 数学模型和求解算法分开表述。
- [ ] 决策变量、目标函数、硬约束、软约束完整。
- [ ] 参数、初值、终止条件、容差、随机种子可复核。
- [ ] 启发式算法用小规模精确解、成熟求解器或简单算法作对照。
- [ ] 随机算法重复运行，保存均值、标准差、最好值、可行率和耗时。
- [ ] 最终方案回代原题逐条检查约束，而非只看“求解成功”。

## 6. 验证与稳健性

- [ ] 至少完成一项与任务匹配的核心检验，而不是统一套“±5%”。
- [ ] 机理模型检查量纲、边界、守恒和数值步长。
- [ ] 统计模型检查残差、分布、共线性、效应量/区间。
- [ ] 预测模型使用独立或滚动验证，并与朴素基线比较。
- [ ] 优化模型报告约束余量、算法稳定性和关键参数阈值。
- [ ] 评价排序检查权重、标准化和方法变化下的稳定性。
- [ ] 分析一个失败/极端情景，并明确模型适用边界。

## 7. 绘图与表格

- [ ] 每图只表达一个主要结论；图题、坐标、单位、图例完整。
- [ ] 灰度打印仍可区分；不用红绿作为唯一编码。
- [ ] 表格小数位和有效数字统一；必要时给基线、误差和约束阈值。
- [ ] 正文先指出读者该看什么，再解释原因与意义。
- [ ] 长中间表放支撑材料，正文只留决策所需信息。
- [ ] 图表数据由代码导出，未从截图或图中手抄。

## 8. 摘要自检

对每一问逐格填写：

| 项目 | 自检问题 |
|---|---|
| 任务 | 这一问究竟求什么/判断什么？ |
| 关键处理 | 最重要的定义、假设或数据处理是什么？ |
| 模型 | 建立了什么关系，而不只是用了什么软件？ |
| 算法 | 怎样估计/求解，关键设置是否必要？ |
| 结果 | 有具体数值、单位、方案或排序吗？ |
| 可信性 | 有误差、基线、检验、敏感性或外部对照吗？ |

- [ ] 摘要可独立读懂，不依赖“见正文”。
- [ ] 没有把背景、模型名和“结果良好”当主要内容。
- [ ] 关键数字与正文、代码输出一致。
- [ ] `[官]` 含题目、摘要和关键词，使用中文，原则上不超过一页。

## 9. 正文与引用

- [ ] 标题层级连续；公式、图、表编号与交叉引用无断裂。
- [ ] 假设都在后文有落点；符号无一字多义且关键量有单位。
- [ ] 每节说明为什么、怎样做、结果和可信性。
- [ ] 结论逐问回答，给建议、条件与限制，不只是复制摘要。
- [ ] `[官]` 正文从摘要页开始编页码；正文不设目录且不超过 30 页，附录置于正文之后。
- [ ] `[官]` 引用他人资料和公开数据时，在正文标注并在参考文献列出；引用位置可追溯。
- [ ] `[官]` 摘要、正文、附录和支撑材料均无身份信息。

## 10. 代码与支撑材料

- [ ] 附录列出支撑材料文件清单。
- [ ] 源码完整可运行；Excel/SPSS 等交互式命令也完整提供。
- [ ] README 写明环境、入口、顺序、预计耗时、输入和输出。
- [ ] 自采数据、长中间结果表和必要说明已提交。
- [ ] 从干净目录实跑，生成的关键结果与论文逐项一致。
- [ ] 不含缓存垃圾、个人路径、密钥、账号或身份信息。
- [ ] `[官]` 没有程序时，在附录明确说明“本论文没有使用程序”。
- [ ] `[官]` 支撑材料为 RAR/ZIP，大小不超过 20 MB；电子论文单文件不超过 20 MB。

## 11. 2026 AI 使用合规

`[官]` 2026 规定允许但不要求使用 AI；参赛队必须主导核心建模并核验输出。隐瞒、虚假声明或未经审查直接采用 AI 生成的核心工作，可能取消评奖资格。

- [ ] 在参考文献之前设置“AI工具使用声明”。
- [ ] 未使用时明确写未使用；使用时简述用途和阶段。
- [ ] 使用 AI 时，在支撑材料提交 `AI工具使用详情.pdf`。
- [ ] 详情包含工具名称与版本、用途/阶段、提示和使用过程示例、采纳/人工修改/验证说明。
- [ ] 语言润色可按规定免于逐项披露采纳细节，但仍应按官方文本正确声明。
- [ ] AI 给出的公式、代码、引文、数据与结论均由队员独立核验。
- [ ] 不让 AI 生成未经理解的核心建模并直接提交。

## 12. 最终提交前双人核验

建议 A 读 PDF、B 按清单查文件，随后交换。

- [ ] PDF 能打开，页序、公式、图片和中文字体正常。
- [ ] 摘要页、页码、正文页数、无目录、附录位置符合规则。
- [ ] 论文题号、文件名和提交系统选择一致。
- [ ] 全局搜索学校、姓名、教师、队号、用户名和本机路径。
- [ ] 全局核对摘要/结论数字与正文主表。
- [ ] 支撑材料在另一台机器/干净目录可解压和运行。
- [ ] 上传后重新下载或预览，核对文件未传错。
- [ ] 保存最终文件哈希或只读备份，避免截止前误覆盖。
